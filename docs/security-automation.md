# Security and supply-chain automation

Frameflow keeps security checks separate from functional CI. The `Security`
workflow runs on pull requests, pushes to `main` or `dev`, manual dispatches,
and every Monday at 04:17 Asia/Seoul time.

## Enforced checks

- Gitleaks scans the complete Git history and redacts findings in logs.
- `npm audit` rejects high or critical production dependency vulnerabilities.
- `pip-audit` audits the hash-locked Python dependency graph.
- Trivy rejects high or critical fixable container vulnerabilities and checks
  repository infrastructure configuration.
- Syft generates SPDX SBOMs for the source tree and the API/Worker and Web
  images. Pull-request artifacts are retained for 30 days.
- GitHub Dependency Review rejects newly introduced high-severity vulnerable
  dependencies after the repository becomes public. The CLI checks remain the
  primary controls while the repository is private.

The API and Temporal Worker share one container image, so one image SBOM covers
both services.

The runtime images execute as UID 1000 and do not contain npm or pip package
installers. Existing installations created before this change may have
root-owned media cache volumes. Preserve the volume contents and migrate only
their ownership once before restarting:

```bash
make migrate-runtime-permissions
make up
```

## Local commands

Docker is required for Gitleaks, Syft, Trivy, and image builds. Python audit
tools are installed in the ignored `.security-venv` directory.

```bash
make security-secrets  # Complete Git history
make security-deps     # npm production graph and Python locked graph
make security-sbom     # Source SPDX and CycloneDX inventories
make security-images   # Build and scan API/Worker and Web images
make security-all      # All of the above
```

Generated SBOMs are written to `artifacts/security/` and are not committed.

## Python dependency lock

`apps/api/requirements.txt` contains the direct dependency constraints.
`apps/api/requirements.lock.txt` is generated by pip-tools and pins the full
dependency graph with package hashes. Development, CI, and the API image install
the lock file with hash verification.

After editing direct requirements, regenerate the lock and run the audit:

```bash
make lock-python
make security-python
make test
```

`requirements-docker.txt` contains the optional media profile. Demucs and
MediaPipe remain separate because Torch is installed from the PyTorch CPU index.
Their resolved contents are inventoried and scanned in the built image.

## Exceptions

Do not suppress a finding only in a workflow command. Dependency vulnerability
exceptions belong in `security/dependency-exceptions.json` and require:

- ecosystem and package
- advisory ID
- concrete reason
- accountable owner
- ISO-8601 expiry date

Expired or malformed exceptions fail the workflow. Rotate a leaked credential
before considering history rewriting; secret findings are never handled as
dependency exceptions. Confirmed Gitleaks false positives use only a finding
fingerprint in `.gitleaksignore` and must have a matching documented review.

## License policy

`security/license-policy.json` classifies SPDX identifiers as allowed,
review-required, or blocked. It starts in `report` mode so the initial inventory
can be reviewed without silently choosing a legal policy. Change `enforcement`
to `block` only after all review-required packages, bundled models, fonts,
FFmpeg components, CLI tools, and sample media have been reviewed.

Frameflow's PolyForm Noncommercial license does not relicense its dependencies.
Every redistributed component must continue to satisfy its own license.

## Maintainer settings

After the first Security run is green, protect `main` and require the `CI` and
`Security` status checks. Keep workflow permissions read-only by default. Raw
secret reports must not be uploaded as workflow artifacts because a report can
contain the value it detected.

Dependabot checks npm, pip, Docker, GitHub Actions, and Terraform weekly. Patch
and minor application dependency updates are grouped; major updates remain
separate for compatibility review.

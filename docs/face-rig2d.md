# Webcam-driven illustrated face rig

`/live-avatar/2d` uses the existing illustration as a face-rig authoring surface.
Expression images are calibration references, not a video or emotion preset
playlist. No GLB is loaded or generated by this path.

## Authoring and use

1. Open **웹캠 얼굴 리그** (the header link scrolls directly to it). The entire
   studio uses one page scrollbar on desktop and narrow screens; the settings pane grows with its contents.
2. In **원본·표정 이미지 기준점 편집**, align the same 36 control points on the
   original and each expression. Eight boundary points remain fixed. Drag points,
   use the X/Y fields, or use arrow keys (0.25px; Shift gives 1px).
3. **MediaPipe 기준점 초안 검출** analyzes the selected artwork locally using the
   pinned Face Landmarker model. It maps representative eye, iris, brow, lip,
   nose and chin landmarks into the artwork coordinate system. It is a draft:
   human-model landmarks can be inaccurate on anime features, particularly thin
   closed lips. Review the image overlay and correct the points before saving.
4. Map the 12 expression channels to their target references. Eight additional
   gaze channels move the iris points directly. **리그 테스트**
   tests continuous strength and combinations without a camera. The independent
   left/right eye and mouth-corner channels are anatomically named.
5. **웹캠 얼굴 연결** starts the face-only capture engine. The separate full-body
   control can drive the body and face together. **얼굴 영상으로 추적 테스트**
   exercises the face-only path with a local recording.
6. Look forward with eyes open and mouth relaxed, then use **무표정 보정**. It
   averages 24 valid frames. A selected channel's **최대값 보정** adjusts its gain
   from the 90th-percentile strength of another 24-frame sample. Insufficient
   motion is rejected. Gain, dead zone, maximum strength and smoothing can also
   be adjusted manually. Capture baselines stay in memory only.
7. **얼굴 리그 저장** saves the rig locally and preserves its reference library.
   **리그 모음 내보내기** includes the reference images, points and channel settings.
   Import validates the original-art hash and all referenced image IDs. Save after
   import to persist it in this browser.

The old gallery remains under **표정 제작 자료 관리** for adding/replacing source
images. It does not override the live rig. **제작 자료 보기** explicitly switches
to static reference review. The default jaw target uses `mouth-open.png`, authored
separately from the laugh image so opening the mouth does not require smiling.
Pre-existing expression libraries receive that reference in the authoring draft
when there is room; their existing images and alignments are preserved.

## Representation

`avatar.face_rig2d.v1` is an authoring document with 8 reference poses, 36 shared
points, 20 input bindings, per-channel response and smoothing. It is separate
from `avatar.puppet2d.v1`, Canvas definitions and published Workflow contracts.
`avatar.face_rig_package.v1` packages the rig and its expression library together.
No new Workflow Node or provider executor is introduced.

Neutral points establish deterministic Delaunay connectivity (62 triangles for
the included rig). Each input channel moves only its assigned feature points;
left/right eye controls and mouth corners are independent. Twelve channels
control expressions and eight directional channels move the iris points within
the eye mesh (up to 4px horizontally and 3px vertically). Gaze displacement fades
during blinking; this is directional gaze estimation rather than screen-point
eye tracking. Overlapping targets
are normalized per point. Eye widening is suppressed while blinking, and a
signed-area check limits deformations that would invert triangles.

Every source image is piecewise-affine warped onto the **same current control
mesh** before facial regions are composited. Mouth-interior appearance is driven
by jaw opening; the image regions for eyes and brows are handled separately.
The output is a small 2× face canvas uploaded as a texture, with unchanged
head alpha and a feathered facial boundary. Original body surfaces and the
independent shoulder work are not reinterpreted by the face rig. Render updates
are capped at 24 FPS and skipped for unchanged strengths.

The face-only session reuses the generic Face Landmarker capture class; it has
no dependency on 3D geometry. Its explicit face-presence flag is processed
without requiring visible hips, shoulders or body landmarks. Full-body Holistic
capture also forwards its face data before the body's confidence gate. Camera
and video frames are bounded to a 720px longest edge in the face-only path to
avoid transferring full-resolution video frames unnecessarily.

Face loss or a 500ms frame gap returns facial values toward neutral. Stop,
navigation and tab hiding release both capture engines, workers and camera
tracks. Late permissions and stale worker errors cannot affect a newer session.
Camera frames are not uploaded or persisted. The actual webcam and the user's
individual calibration remain user-run; QA uses a local prerecorded face crop.

## Quality boundary

This is a tunable 2D deformation rig, not a reconstructed 3D head, a full Live2D
Cubism rig, or an emotion classifier. The neutral face stays the original image.
Sparse control points, piecewise-affine interpolation and the resolution of the
reference art limit fine contours. Source points and response curves should be
calibrated on the user's webcam. Large profile turns, additional lip shapes need separately authored controls and references.

- `npm run test:face-rig2d --workspace apps/web`: point/binding validation,

## Face-first entry

From `/live-avatar`, choose **2D 웹캠 얼굴 리그** to open `/live-avatar/2d/face`. This uses the same saved 2D rig and expression references, starts in a neutral body pose with the face enlarged, and places face tracking controls first. Connect the webcam, calibrate neutral, then adjust channel response and save the rig. The camera preview appears beside the avatar; permission and tracking errors appear in the face panel. Camera access begins only after the user presses connect. `/live-avatar/2d` keeps the full-body authoring layout.

## Inspecting facial correspondence

Use **웹캠·아바타 리그 비교 표시** to draw the actual deformation mesh over the character, including fold protection. Cyan points mark eyes, green irises, pink brows, and orange lips; white segments show displacement from neutral. The selected channel shows raw MediaPipe input and the calibrated rig value together. Use neutral calibration and selected-channel maximum calibration before adjusting source landmarks. Eye and brow rendering now warps the original artwork without crossfading generated eye plates, preventing duplicate lashes/brows from mismatched references. Jaw opening is added independently of smile/frown controls so smiling does not dilute an open mouth. Generated mouth artwork still requires accurately aligned reference points; these changes do not provide head rotation or unseen facial artwork.

## Comparing webcam landmarks

Enable **웹캠·아바타 리그 비교 표시** while tracking. The enlarged camera inset overlays the detected face landmarks and highlights corresponding eye, brow, lip and iris features in the same colors as the avatar mesh. The face-first comparison inset displays both video and overlay without mirroring so anatomical left/right match the avatar, with the original video aspect ratio preserved. The normal camera preview remains mirrored. Undetected/stale landmarks clear automatically. These are detected human landmarks, not a second authored avatar rig: compare semantic feature positions and channel values, not raw coordinates between two different faces.

## Brow and mouth alignment

**본체 눈썹·입 맞추기** aligns eyebrow targets to the current eye centers while preserving their authored animation deltas. Independent left/right height, shared width and inner-corner tilt tune the resting brows. Mouth targets center on the face midline with width, vertical offset and opening scale. All source pose points remain unchanged; aligned targets pass through the existing fold guard and are shown in mesh debug. The mouth texture mask now follows actual deformed mouth bounds with a small margin instead of a large fixed oval.

Quick tests include raised brows, one-sided brow down, smile, open mouth and smile+open. ## Independent generated eyebrow layers

`brows-v1/brow.png` is a newly generated transparent eyebrow sprite, mirrored for the opposite side. `clean-base.png` is an image-generated eyebrow-free backing; only its narrow brow band is composited, leaving other artwork intact. Full prompts live beside these assets. A strip mesh bends the sprite through inner/middle/outer control points, with independent left/right channels, shared width/tilt and new thickness control. The old brow vertices are held at rest in the face mesh, so brow inputs do not deform bangs. Dark hair from the clean plate supplies a fixed occlusion overlay.

Visual QA found eyebrow-raise differences bounded to `(334,318)-(448,333)` in the 797×730 preview; upper-hair pixels were unchanged. Preset, local face-video and saved-settings checks passed. This supersedes the prior paragraph describing non-isolated eyebrow deformation. Mouth rendering remains on its existing implementation.

## Clean head v2

`head-v2/clean-head.png` redraws the face/hair without baked eyebrows or floating eyelid crease lines. AvatarStudio passes it as the optional head replacement to PuppetScene; only the original head alpha is recolored, with original body assets and silhouette retained. FaceRigRenderer uses the same clean head for its neutral plate, and the independent brow renderer uses it for hair occlusion. The previous narrow-band backing patch is removed. Original expression library documents and body/shoulder sources are not rewritten. **독립 눈썹 표시** toggles the separate brows for verification. This exposes whether a stroke is in the backing or rig. The generated full-body PNG is an input carrier; only its head is applied.

## Nine-point eyebrow controls

Each independent eyebrow now exposes nine controls (inner=1, middle=5, outer=9). Each has editable X/Y offsets and expression-response gain. The renderer interpolates local adjustments between these controls over the existing three-anchor motion, preserving old appearance at zero offsets/gain one. These are editable render controls, not eighteen new MediaPipe channels. The detailed editor shows numbered points; body mesh debug shows all eighteen brow points. Defaults preserve existing rig documents. **얼굴 리그 저장** stores them in `frameflow.brow-detail.v1`; the older portable package does not yet include this separate authoring record.

Validation: `node --experimental-strip-types apps/web/scripts/test-brow-detail.mjs` checks control independence, response gain, interpolation and legacy defaults.

## Eyelid contour rig

The body eye renderer now uses independent upper/lower contour controls (nine per contour per eye, with fixed shared corners). Blink moves both contours to one shared seam according to the authored upper-lid travel share; eye-wide expands the aperture. Sclera fill, spherical iris/pupil, aperture clipping and lash outlines are separate render operations. The old vertically compressed sclera/closed-sprite crossfade is replaced. Lash outlines follow the rig curves, so their stroke thickness is preserved through closure.

**눈꺼풀 리그 · 위·아래 각 9점** supports side/edge/point selection, contour height, upper-lid travel ratio, manual blink presets, webcam return and per-eye reset. Save uses `frameflow.eyelid-rig.v1`; older portable packages omit this separate preference. The UI does not claim independently tracked squint or pupil dilation.

Validation: `test-eyelid-rig.mjs` checks exact closure, fixed corners, contour order, independent eyes and parsing; `output/eyelid-rig/qa.cjs` checks body open/half/closed, edits, saved reload and face-video input.

## Independent mouth contours

**입모양 리그 · 위·아래 각 9점** adds independent upper/lower lip controls, fixed shared corners, teeth/tongue visibility and manual closed/small/large/smile/asymmetric/frown presets. Five existing calibrated mouth channels drive the geometry. Smile shifts each corner relative to the mouth center; jaw opening remains independent of smile, and upper/lower contours coincide at closure. The mouth interior, teeth and tongue are clipped to the aperture. This is a procedural stylized mouth renderer, not newly generated mouth artwork or phoneme recognition. Existing expression-reference images remain in the authoring library but no longer crossfade into the live mouth.

The face mesh's mouth anchors stay at rest to avoid double deformation. The rendered contour controls appear in debug. Preferences save separately as `frameflow.mouth-rig.v1` and are omitted from the older portable rig package. Validation: `test-mouth-rig.mjs` and `output/mouth-rig/qa.cjs`.

## Upper teeth without jaw opening

The mouth layer consumes two additional runtime motion channels, `mouthUpperUpLeft` and `mouthUpperUpRight`. They share neutral-baseline calibration, smoothing and stale-face reset with the existing twenty channels, while the original profile/config channel contract remains unchanged. The renderer's frame signature includes these signals. Upper-lip lift opens the aperture independently of jaw motion and keeps lower-lip geometry fixed; the upper teeth row stays fixed in mouth coordinates and is revealed by the lip mask. Tongue rendering requires actual jaw opening.

**윗니만 드러내기** resets jaw to zero and raises both upper-lip channels. Separate left/right manual controls, raw/applied values, and persisted `upperLipGain` in the mouth preference record support calibration. Existing mouth preferences default to gain one. New runtime channels are not exposed in the old general profile-channel dropdown. Validation: `test-upper-teeth.mjs` and `output/upper-teeth/qa.cjs`.

## Additional mouth actions

Ten extra runtime channels add lower-lip depression (left/right), pucker, funnel, press (left/right), upper/lower lip roll and stretch (left/right), for 32 total runtime face channels including the previously added upper-lip pair. The legacy profile still contains its original twenty configurable channels. Extra channels share neutral calibration/smoothing/reset and appear in **추가 입동작 · 원본과 적용값** with individual manual sliders.

Lower teeth are revealed by lower-lip depression, pucker narrows the mouth, funnel adds a rounded opening, press compresses the aperture, roll reduces aperture/stroke prominence, and stretch pulls corners separately. These are stylized procedural approximations, not speech/phoneme recognition or physically simulated lip tissue. Six presets and individual controls were verified in browser along with local face-video input. Tests: `test-mouth-actions.mjs`; screenshots and browser checks in `output/mouth-actions`.

## Manual tongue rig

The mouth preference record now optionally stores `tonguePose: {x,y,out,curl}`, defaulting to neutral for existing records. Manual sliders/presets move the tongue inside the mouth and extend a separate foreground tongue over the lower lip. Aperture-derived gating hides it on closure; visibility still respects the tongue checkbox. It does not add fake tongue channels to MediaPipe tracking. The standard Face Landmarker Blendshapes enum has no tongue coefficients: https://ai.google.dev/edge/api/mediapipe/python/mp/tasks/vision/drawing_styles/face_landmarker/Blendshapes . Automatic tongue tracking requires a separate detector/source and is not implemented.

Tests: `test-tongue-rig.mjs` covers axes, extension, curl, closure and legacy defaults; `output/tongue-rig/qa.cjs` covers five poses, closed-mouth pixel equality and saved reload.

## Complete MediaPipe motion mapping

`FACE_MOTION_CHANNELS` now contains all 51 non-neutral Face Landmarker blendshapes. The additional nineteen comprise outer brow raises, eye squints, forward/lateral jaw motion, mouthClose/dimple/lateral/shrug, cheek puff/squint and nose sneer. Neutral is displayed as reference telemetry only, not a deformation. Tongue controls remain explicitly manual. Existing profile channel records are unchanged; runtime-only extra signals share neutral calibration, smoothing, render invalidation and stale reset.

Outer brow raises feed the separate brow controls; squint raises lower lids while lowering upper lids; jaw and cheek/nose values deform the facial control mesh; mouthClose suppresses lip separation without zeroing jaw input; dimple/lateral/shrug deform the mouth separately. Forward jaw, cheek volume, dimple and nose movement are stylized 2.5D approximations, not a physically complete facial model. The **전체 MediaPipe 채널** panel exposes all 51 selectable channels, raw/applied values and isolated/manual-combination testing.

Validation: `test-all-face-channels.mjs` checks unique count, calibration and each new mapping. `output/all-face-channels/qa.cjs` checks every additional channel yields a rendered change (mouthClose against an open-jaw baseline), plus local face-video input. This verifies wiring, not tracking accuracy across all users/lighting conditions.

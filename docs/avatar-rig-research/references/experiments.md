# 2D·2.5D 아바타 리그 실험 노트

작성일: 2026-09-09 (Asia/Seoul)

## 현재 판정

**연구 진행 중 / 최신 사용자 시각 평가: 실패.**

현재 어깨 실험은 접합과 수치 안정성 일부를 확보했지만 자연스러운 어깨·겨드랑이 변형은 확보하지 못했다. 최신 사용자 이미지에서는 위팔 아래 피부가 옆구리까지 긴 막처럼 연결되고, 어깨와 겨드랑이의 윤곽·음영이 부자연스럽다. 남은 문제를 음영만의 문제로 축소하지 않는다.

이 문서의 순서는 대화에서 관찰된 실험 순서다. 개별 실험을 분리한 Git 커밋이나 완전한 비교 영상은 없다. 초기 3D·머리카락 실험은 대화 기록에 따른 요약이며 이번 문서 작성 중 재실행하지 않았다.

## 사용자 목표와 범위

- 참고 영상 같은 그림체, 음영과 원근이 있는 2D/2.5D 아바타를 사용자 움직임으로 제어한다.
- 목적은 영상 생성 결과를 얻는 것이 아니라, 어떤 리그 연결이 좋은 연속 변형을 만드는지 연구하는 것이다.
- 큰 관절을 자연스럽게 만든 다음 손가락 등 미세 관절로 진행한다.
- 현재 대상은 캐릭터의 왼쪽 어깨, 즉 화면 오른쪽이다.
- 수동 팔 벌림 한 축으로 입력을 고립한다. 카메라·MediaPipe·머리 흔들림·동적 조명은 이 실험에서 제외한다.
- 의상은 흰 민소매와 검정 반바지다. 민소매가 위팔과 함께 통째로 끌려 올라가는 것은 사용자가 거부했다.
- 참고 영상: `http://localhost:3000/asset/videos/art_d78356242bc4494495`
- 실험 화면: `http://localhost:3000/live-avatar/2d/shoulder`
- 본 화면: `http://localhost:3000/live-avatar/2d`

참고 영상의 내부 제작 방식은 확인하지 못했다. 외형만 보고 Live2D, 3D 셀 셰이딩, 특정 생성 모델이라고 단정하지 않는다.

## 현재 구현의 의미와 한계

`shoulder-lab-model.ts`는 각도에 따라 어깨를 최대 위로 32px, 안쪽으로 9px 이동시킨다. 팔꿈치·손목 상대 각도와 뼈 길이는 고정한다. 이 값은 이 그림을 위한 임의 보정이며 해부학적 모델이 아니다.

`shoulder-surface.ts`는 흉곽/왼팔 외곽을 합친 메쉬를 만들고 삼각형 세분화·내부 대각선 교환, cotangent ARAP, 양의 면적 보정을 적용한다. 겨드랑이 기준은 원화 좌표 `[613,440]` 한 점이다. 이 위치는 실제 겨드랑이의 앞·뒤 경계를 검증해 도출한 좌표가 아니다. 어깨, 위팔, 흉곽의 부피나 표면 법선 구조도 충분히 정의되어 있지 않다.

2° 간격 캐시는 동일한 변형 알고리즘의 결과다. 검수된 올바른 자세 예시나 정답 데이터가 아니다. 메쉬가 연결되고 뒤집히지 않아도 막처럼 늘어날 수 있다.

`shoulder-garment.ts`는 수동 폴리곤으로 민소매를 추출한다. 피부 하부에는 선형 색상 그라디언트를 채운다. 숨은 겨드랑이 면을 제작한 것이 아니며, 선화·표면 방향·가림·접힘 정보가 없다.

`garmentPoint`는 목선·가슴·밑단을 거의 고정하고 바깥 끈에 최대 8px 상승/1.8px 안쪽 이동을 허용한다. 이것도 실제 의상의 부착/접촉 모델은 아니다.

## 검사가 증명한 것과 증명하지 못한 것

이전 구현 턴의 결과이며 문서 작성 턴에서는 애플리케이션 검사를 재실행하지 않았다.

- `test:shoulder-lab`: 641개 각도(0–160°, 0.25° 간격), 연결 그래프, 양의 삼각형 면적, 뼈 길이/팔꿈치 상대 각도, 비대상 관절 고정, 기준 메쉬 복원, 입력·왕복·메모 검사를 통과했다.
- 의상 검사: 몇 개의 목선/가슴/밑단 표본점 고정과 끈 표본점 이동 상한을 확인했다. 의상 전체의 시각적 자연스러움 검사가 아니다.
- 마지막 수치: 최소 면적비 약 0.1200, 최대 에지 길이비 약 5.0634, 인접 0.25° 입력 사이 최대 정점 이동 약 6.2054 원화 픽셀.
- 현재 테스트 한계: 에지 길이비 `<6`, 이동 `<8`은 느슨한 회귀 방어선이다. 약 5배 늘어난 에지가 있어도 통과하므로 자연스러운 피부라고 판정할 수 없다.
- `neutral artwork`라는 테스트 메시지는 실제로 정점 좌표 복원을 검사한다. 새 피부색 채움/마스크/합성 이후 최종 픽셀의 동일성을 증명하지 않는다.
- `test:avatar-2d`: 854개 참고 프레임에 대한 기존 입력/길이/픽셀 소유권 관련 검사를 통과했다. 새 어깨 실험의 완성도를 증명하지 않는다.
- 최종 의상 수정 턴에서 build, typecheck, lint, ui:check 통과를 확인했다. 현재 작업 트리는 다른 작업에 의해 달라질 수 있다.
- 브라우저에서 기준·90°·135°·160° 등을 보았으나 후속 사용자 평가가 실패였다. 이전 어시스턴트의 완료 표현보다 사용자 평가를 우선한다.
- 로딩 중 각도 샘플 준비로 조작 불가 상태와 도구 타임아웃을 관찰했다. FPS·p95 지연의 정식 측정은 하지 않았다.

## 연구 가설: 아직 구현·검증하지 않은 것

### H1. 의미 있는 보조 제어가 단일 어깨 축보다 적합하다

흉곽, 어깨대/쇄골 근사 제어, 위팔, 어깨 외곽, 겨드랑이 앞·뒤 경계를 역할별로 둔다. 사용자 입력은 한 축으로 유지하고 보조 제어를 연동한다. 제어 수나 해부학적 회전 비율을 미리 정답으로 고정하지 않는다.

### H2. 자세별 보정 형태가 큰 각도의 윤곽을 안정시킨다

기본 뼈/가중치 변형에 검수된 기준 자세의 정점 보정을 추가한다. 모든 프레임 이미지를 등록할 필요는 없으나, 단일 원화에 없는 면이나 깊은 회전의 외형은 별도 제작이 필요할 수 있다. 0°·45°·90°·135°·160°는 초기 표본 후보다.

### H3. 피부 연결과 의상 연결의 의미가 다르다

피부는 경계 대응/공유 정점으로 접합하되 영역별 변형을 분리한다. 옷은 같은 몸 골격을 참조하더라도 별도 표면과 가중치를 가진다. 민소매의 가슴 패널, 끈, 암홀, 옆선/밑단에는 다른 부착·접촉·변형 규칙을 적용한다. 옷을 완전히 고정하는 것도 보편 정답은 아니다.

### H4. 물리는 기본 자세 이후에 평가할 가치가 있다

정지 각도에서의 결함은 먼저 리그·형태·가중치로 해결한다. 스프링/감쇠는 지연·흔들림에, XPBD 등은 늘어남·굽힘·접촉에 사용할 수 있다. 천의 기준 형태, 재질, 부착점, 충돌할 몸의 형태가 없으면 엔진 도입만으로 해결되지 않는다.

### H5. 제한적인 3D 내부 형태가 2.5D 확장에 유용할 수 있다

화면은 2D로 유지하고 내부에 흉곽 타원체·위팔 캡슐 등 간단한 형태를 둘 수 있다. 앞뒤 이동, 깊이, 가림, 옷 접촉, 음영 방향을 검증할 때 비교한다. 현재 정면 한 축 실험에 필수라고 결론 내리지 않았다.

## 다음 실험: 단색 왼쪽 어깨 형태

목표: 기준 형태를 설명할 수 있는 최소 리그로 어깨·위팔·겨드랑이의 단색 실루엣을 재현하고 중간 각도를 연결한다.

1. E08을 실패 비교군으로 보존하고 별도 후보로 작업한다. 화면 배율, 원화, 입력 축, 각도는 동일하게 둔다.
2. 옷·원화 음영을 숨긴다. 단순히 옷 아래 색을 채운 결과가 아니라 피부 영역/경계를 먼저 정의한다.
3. 어깨 외곽, 겨드랑이 앞·뒤 경계, 흉곽 접합 위치, 위팔 두께의 기준을 만든다. 참고 영상 프레임을 쓸 경우 원근과 몸통 기울기 차이를 기록한다.
4. 비교군: 최소 뼈/가중치 → 의미 있는 보조 제어 → 자세별 보정. 메쉬 밀도와 물리는 별도 변수로 둔다.
5. 정지 각도에서 형태가 타당해진 뒤 중간 각도, 역방향 왕복, 임의 각도 접근을 검사한다.
6. 피부 결과가 통과한 다음 민소매를 추가한다. 이후 필요한 물리·음영을 평가한다.

평가 항목: 접합 틈, 외곽선 오차, 위팔 단면 폭 변화, 겨드랑이 막의 면적/길이, 접힘·가림의 타당성, 의상 특징점 이동, 정점/윤곽의 튐, 조작 지연. 측정 위치와 허용치는 기준 자세를 보고 실험 전에 제안한다. 임의 임계값을 자연스러움의 정답으로 사용하지 않는다.

실패하면 같은 후보에 색/조명/패치를 덧붙여 통과시키지 말고 가설을 수정한다. 손가락·표정·전체 트래커로 범위를 확장하지 않는다.

## 참고한 1차 자료

아래 자료는 기법의 근거다. 현재 캐릭터의 성공을 보증하지 않는다. 이전 분석 턴에서 조회했으며 스킬 적용 시 버전별 동작이 중요하면 다시 확인한다.

### 단색 기준 형태의 정의와 한계

좌표는 원화 1024×1536, x 오른쪽/y 아래다. 상체 오른쪽 절반과 위팔을 팔꿈치에서 자른 경계로 표시한다. 왼쪽 세로선과 팔꿈치 끝 직선은 관찰 영역의 절단선이며 해부학적 윤곽이 아니다. 전체 보기라는 파일명은 **이 연구 영역 전체**를 뜻하며 전신이 아니다.

- 어깨: 목 옆 기준 `[579,313]`에서 위팔 바깥으로 둥글게 연결되어야 한다. 제어점 위치 일치만으로 충분하지 않으며 접선 반전, 뿔, 깊은 패임은 실패다.

## E10 — 90° 연결점의 접선 방향만 정렬 (2026-09-09)

**판정: 부분 성과. 90° 국소 돌출·꺾임 개선 확인 / 전체 피부 자연스러움 미검증.** E09의 다른 각도 실패와 E08의 사용자 실패 판정은 유지한다.

### 가설과 실험 전 기준

관찰: E09 B의 90° 어깨에는 작은 돌출과 패임이 함께 있으며, 겨드랑이에는 날카로운 모서리가 있다. 가설: 같은 연결점에서 들어오는 접선과 나가는 접선의 방향 차이가 이 결함에 기여한다. 연결점 위치를 또 옮기지 않고 접선 방향만 맞추면 결함을 줄일 수 있다.

판정 기준은 실험 전에 다음으로 정했다.

- 시각: 어깨 외곽의 작은 뿔·패임 제거, 겨드랑이 모서리를 짧은 오목한 연결 곡선으로 대체. 단색·동일 배율에서 전체 연구 영역과 확대를 함께 평가.

### 비교군·변수·기준 곡선

A는 `contourPose(90,"helper")`, 즉 E09 B 그대로다. B는 A를 복사한 뒤 **접선 방향만** 바꾼다. 연결점이나 핸들의 길이를 바꾸지 않는다. 11개 cubic/176개 경계 표본, 동일 축과 위팔 길이, 옷·음영·물리 없음 조건을 유지한다. E09 원본 코드는 수정하지 않았다.

| --- | --- | --- |

A는 E11의 `aligned` 결과다. B는 목→어깨 cubic 구간 1의 시작/끝 핸들 **길이만 같은 배율로 줄인다**. 다른 연결점·방향·10개 곡선·뼈·11구간/176표본·옷/음영/물리 없음 조건은 고정한다.

- 가로 여유 `g = end.x - start.x`.
- 양의 핸들 투영 `a = firstHandle.x - start.x`, `b = end.x - secondHandle.x`.
- 길이 배율 `s = min(1, g / (a+b))`.
- 끝점에서 핸들로 향하는 벡터에만 `s`를 곱한다. 접선 방향은 유지한다.

임의의 px 길이나 각도별 새 키를 찾지 않았다. 두 핸들의 x 투영 합이 가로 여유를 넘지 않게 하여 네 제어점의 x 순서를 유지한다. 이 구간의 x 도함수 최솟값은 이차식의 끝점과 내부 극값을 계산해 구한다. 촘촘한 각도 샘플로 자연스러움을 증명하려 하지 않는다.

`g<=0` 또는 뒤로 향하는 접선이 들어오면 이 정책은 명시적으로 거부한다. 그런 상황은 끝점 배치/접선 정책의 다른 가설로 다뤄야 한다. 현재 구현은 45°·90°·135° 정지 자세에 한정된다.

## E14 — 0° 앞뒤 순서가 겨드랑이 틈을 해결하는가? (2026-09-09)

**판정: 해결하지 못함. 0° 정지 피부 연결 실패 유지.** 팔 앞/몸통 앞 모두 같은 작은 틈이 남았다. 표시 순서만으로 이 고정 형태의 틈을 없앨 수 있다는 가설은 기각한다. 다른 리그에서 가림 처리가 불필요하다는 뜻은 아니다.

### 검사 전 범위와 비교 설계

기존 0° helper는 하나의 자기교차 경계이므로 그대로는 팔/몸통 표시 순서를 바꿀 수 없다. A는 E09의 원래 단일 경계로 보존했다. B/C에 공통으로 다음 **진단용 분할**을 만들었다.

- 팔: 원래 곡선 2~6 + 겨드랑이→어깨 외곽점의 직선 닫힘.
- 몸통: 원래 곡선 0~1, 외곽점→겨드랑이의 직선 닫힘, 원래 곡선 7~10.
- 닫힘 직선은 같은 두 점을 역방향으로 연결한다. 독립적으로 검증된 피부 내부 경계가 아니다.
- B는 몸통을 먼저 그리고 팔을 앞에, C는 반대로 그린다. **B/C의 유일한 차이는 그리기 순서**다.

기존 외곽 곡선/뼈/제어점은 수정하지 않았다. 구간당 표본 수 16은 같다. A는 11구간/176표본, B/C의 두 영역 합계는 내부 닫힘 두 구간이 추가되어 13구간/208표본이다. 메쉬를 고밀도화한 것이 아니지만 A와 B/C의 표현이 같다고 주장하지 않는다. 통제 A/B 비교는 B↔C이며, 원래 A와의 차이는 분할/채움 효과로 따로 점검한다.

사전 기준: 두 순서의 단색 실루엣은 같아야 하며, 틈과 피부 돌출/두께를 전체·확대에서 확인한다. 가려진 경계 표시로 잘못된 연결이 숨겨지는지도 확인한다. 피부 정지가 실패하면 낮은 인접 각도/왕복으로 진행하지 않는다.

### 수치 결과와 측정 한계

SVG 기본 `nonzero` 채움에 맞춰 경계 winding number로 점 포함 여부를 계산했다. 영역 `[505,305]`~`[675,550]`, 0.5px 간격 격자의 셀 중심을 평가했다. 바깥 배경을 flood-fill한 뒤 내부에 남은 빈 영역을 찾았다.

| 항목 | 결과 |
| --- | --- |
| 팔/몸통 겹침 투영 면적 | 약 382.25px² |
| B/C 순서에 따른 단색 포함 영역 차이 | 0px² |
| 분할 후 A 대비 추가/제거 영역 | 0 / 0px² |
| 닫힌 빈 영역 | 1개, 약 2px² |
| 빈 영역 셀 중심 평균 | `[611.1875,397.875]` |
| 해당 중심점의 팔/몸통 포함 여부 | 둘 다 밖 |
| 기존 경계 교차 | 2, 그대로 유지 |

이 수치는 고정 경계 표본과 0.5px 격자에 의한 **투영 면적 근사**다. 실제 피부 면적, 메쉬 변형률 또는 브라우저 픽셀 완전 일치 검사가 아니다. B/C 불투명 단색의 포함 영역이 같은 것은 합집합이 그리기 순서와 무관하다는 성질과 일치한다. 안티앨리어싱 경계까지 픽셀 동일함을 주장하지 않는다.

### 시각·조작 판정

- **시각 실패:** 실제 Chrome의 단색 확대/전체에서 A/B/C 모두 같은 겨드랑이 구멍이 보인다. 팔 앞과 몸통 앞을 바꿔도 사라지지 않았다. 원위 팔과 몸통 외곽은 그대로다.
- **소유권 진단:** 진단색에서는 겹친 영역의 보이는 주인이 바뀐다. 팔 앞에서는 각진 안쪽 경계가, 몸통 앞에서는 몸통 경계가 드러나지만 틈은 둘 다 남는다. 색은 소유권 확인용이며 피부 형태 수정에 쓰지 않았다.
- **숨은 경계:** 팔/몸통 전체 외곽과 추가 내부 닫힘선을 표시해 미검증 경계가 단색에서 숨겨질 수 있음을 확인했다. 어느 표면을 앞에 두는 것이 해부학적으로 맞는지 결정할 자료는 이번 비교에 없다.
- **조작:** 확대/진단색/숨은 경계 토글 확인. 0° 고정 실험이며 인접 낮은 각도, 왕복, FPS/입력 지연, 의상/물리는 미평가다. UI 셸의 API offline 표시가 있었으나 E14는 API/카메라를 사용하지 않는 로컬 경계 검사다.

**결론:** 이 틈은 두 영역 중 하나로 가려질 겹침이 아니라 두 영역 모두 덮지 않는 곳이다. 앞뒤 표시만 바꾸는 방식은 해결책이 아니다. 기존 경계 교차도 유지되어 피부 리그 통과로 판정할 수 없다.
